# 增量版 PRD

按 SKILL.md 共用规则交付已定稿大版本，首次建立完整交付基准，后续说明大版本变化。版本冻结及交付边界见“需求基线”。

## 写前核对

- 确认产品团队已确认并冻结最终全量版 `vX.Y`，记录版本及可核验的修订版本或快照入口，确保能还原交付当时的正文与图示。仅有后续改写的全量版时，说明缺少交付当时依据并索取。
- **首次 `v1`**：注明无前版，以当时冻结的全量版 `v1.Y` 完整正文为范围；缩小范围须由使用者明确指定，并记录范围及出处。
- **后续大版本**：取得上一已交付大版本对应的最终全量版或可核验快照，逐项比较新增、修改、移除及全量版精确位置，不从现版猜旧行为。
- 资料／设计冲突按共用规则裁定，不编造差异。读取历史版本或快照仍须遵守共用归档访问限制。

## 开头与正文

标题含本轮大版本 → 相关资料入口表 → 正文。资料表依共用规则，含本轮最终全量版及其冻结依据、上一已交付大版本基线及相关 Figma 原型／UI；首次注明无前版。

增量版是稳定交付件，只标本轮大版本及对应全量基线，不设版本管理表、历史变更记录，不继续维护小版本。不要求封面，不套全量版章节结构，正文仅两章：

1. **本次增量总览**：用导图、流程图或表格让开发先抓全局。首次概括交付范围、受影响功能与协作方；后续概括新增／修改／移除及影响。
2. **按全量版 PRD 分点说明细节变化**：首次按原章节顺序分节承接完整正文，执行下节要求，不假造旧行为；后续按对应功能给出全量版精确位置，写清上一已交付大版本行为 → 本轮最终行为，必要的界面、规则、数据、状态、异常、恢复、依赖、配合、验收要求随变化展开。后续交付中，未变完整定义只链接，不复制或另造定义；动态任务、Bug、实际验收结果指向现行记录。

## 首次交付的完整承接

- 保留原始正文中的术语、流程、规则、字段、数值、状态、异常、恢复、依赖、非功能要求、埋点、验收条件、图示、来源链接及人工填写内容。允许按两章结构重新组织，必须保持信息完整、含义一致，不以摘要或链接替代正文。
- 待确认、待补充、冲突及空章如实保留，不擅自裁定或补造信息；已有图示的信息及原生可编辑性完整保留。原文问题反馈使用者裁定，修改任务按共用“跨载体一致”同步全量版、增量版及其他受影响位置并复查，审阅仅报告。
- 一致性覆盖全量版正文；封面、版本管理表和文末变更记录依本文件的增量版格式处理。完整承接用于历史交付留存，当前完整定义仍以全量版为准；后续比较定位到该次交付对应的最终全量版或可核验快照。

## 交付检查

在实际范围内执行 SKILL.md 共用核验，并检查：

- **依据**：标题大版本与全量基线对应，资料表可到达本轮最终全量版、能还原交付当时内容的修订版本／快照及相关设计；有前版时可到达上一已交付大版本基线，首次注明无前版。
- **首次完整性**：双向核对“全量正文每项信息及图示 → 首次增量版落点”“首次增量版每项定义 → 当时全量版位置”，逐项确认数值、条件、关系、确认状态及人工内容一致，空章保留；使用者指定缩小范围时按已记录范围核对。执行记录保留位置对应及实际检查依据。
- **后续覆盖**：逐功能双向核对“发现的每项新增／修改／移除 → 正文说明”“正文每项变化 → 基线位置”，覆盖整个大版本，非本轮最后两小版之差；未变完整定义仅链接。
- **问题与缺口**：发现遗漏、摘要替代正文或含义改变，修改任务修复并复查，审阅报告。原文、图示、冻结版本或所需基线读取不全时，完整性标待验证，说明具体缺口，继续可核验部分，不宣称完整交付。
- **内容与唯一性**：总览清楚，内容可定位，必要依赖与验收完整，按首次／后续分流检查；无版本／历史表，同大版无并行第二份增量版。
- **成品**：图示主流程、关键分支、真实页面及来源符合共用规则，原生节点可编辑；实际表格、自动标题编号及间距通过共用检查。
