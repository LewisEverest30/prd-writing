# 增量版 PRD

供开发接收一个已定稿的大版本。每个 `vX` 只对应一份增量版，比较本轮最终全量定义 `vX.Y` 与上一已交付大版本的最终定义；本轮中间的小版本不逐篇交付。

## 写前核对

1. 确认 `vX.Y` 已作为本轮最终全量版定稿，并找到上一已交付大版本的最终全量版或可核验的版本快照。不能从当前定义猜测旧行为；首次交付则写明没有前版，不假造「原有行为」。
2. 逐项比较两版已确认的需求定义，找到新增、修改和移除的行为及其全量版精确位置。原型、UI 和需求记录给具体入口；资料冲突先请用户裁定。
3. 若 `vX` 已交付开发，后续需求变更进入 `v(X+1).0`；不要改写已交付的 `vX` 增量版。仅需纠正文字、链接等非需求错误时沿用版本并用修订历史留痕。

## 文档结构

1. **本次增量总览**：用思维导图、主流程图或表格简明说明本轮新增、修改、移除的范围、受影响功能和协作方。写明 `vX`、对应最终全量版 `vX.Y`、上一已交付大版本及其精确链接；首次交付注明首次范围。
2. **按全量版 PRD 分点说明**：逐点给出现行全量版的精确位置，说明上一大版本行为 → 本轮最终行为，以及必要的界面、规则、数据、状态、异常、恢复、依赖和验收变化。没有变化的完整定义只给链接，不复制。动态任务、Bug 和实际验收结果指向现行记录。

增量版不要求封面或全量版的第 1–5 章。交付前核对：读者能从总览确定本轮边界，开发能逐项定位变更与验收；版本号与所指全量版一致，且同一个 `vX` 没有第二份并行增量版。
