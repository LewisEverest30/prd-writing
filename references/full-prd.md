# 全量版 PRD

面向产品内部，维护能力的当前完整定义。按入口共用规则核对事实源、原型和约束，再按以下结构编写。具体功能按需展开，不为填满模板制造内容。

## 封面与文档开头

全量版必须有文档封面。优先生成符合功能主题、视觉克制且有高级感的高清封面，可参考飞书标准封面的视觉风格并融合文档功能意象；生成图片最终尺寸严格为 2000×400 像素，检查清晰度和裁切。生成条件不具备或效果不达标时，选择合适的飞书内置封面。封面只作视觉表达，不冒充真实产品界面或硬件规格。

在飞书中将封面设置为文档封面资源，并回读确认已生效；仅有本地图片或正文插图不算完成封面设置。

开头顺序为：封面 → 版本信息短表 → 相关资料入口表 → 正文。基本信息直接平铺，不设“第 0 章”，不参与正文编号。

### 版本信息短表

版本管理与基本信息合在一张短表中，只有一行当前信息。五列依次为 `当前版本｜状态｜审核人｜创建日期｜本版变化`。不使用“项目｜内容｜项目｜内容”表头，不出现“（既有编号）”等对读者无用的说明。

“本版变化”表头内放可点击链接，链接文字为“详细变更记录见文末”，指向文末记录；不另设历史版本列。表内只用一句话概括本版变化，完整历史不堆在文首。审核人等未知字段标明待确认，不虚构。

### 相关资料入口表

版本表后、第一章前放“相关资料入口”表，具体内容按入口的共用约定填写。

## 正文五章

正文按以下顺序组织，序号由飞书生成：

1. **全文概述**：保留三个小节。
   - **背景与设计动机**（1.1）：简述背景、问题和设计动机，已有分析引用出处。
   - **名词解释**（1.2）：用表格解释必要术语，已有权威定义直接引用。
   - **全文总览**（1.3）：使用思维导图概括整篇 PRD 的主旨和内容结构，帮助读者理解全文；在飞书中交付原生可编辑导图，不以表格或文字清单代替。这里总览全文，第二章呈现功能使用流程。
2. **功能设计**：章首先呈现本 PRD 所描述功能的整体使用流程，优先采用流程图、时序图等能表达操作顺序和交互过程的图表，让读者看清入口、主要步骤、关键分支与结果。不建议用思维导图或仅展示分类的功能结构图替代章首流程总览；此类图可作为功能范围、组成与关系的补充。并列功能按各自主线表达，不虚构先后依赖。再按功能点组织二级标题（2.1、2.2……），每节先呈现嵌入关键 UI／原型页面的功能图，再补结构化文字，具体编排和章首总览的配图要求见下方“第二章图示与小节写法”。章首总览与各节功能图遵守入口的主要步骤、关键分支和原生可编辑要求；全流程图的“完整”指覆盖业务流程，不要求细化到每个页面、按钮或字段。
3. **非功能需求**：按具体问题写实际需要的要求、适用条件和验证方式；无依据的数值不自行确定。
4. **埋点、分层等**：保留该章，暂时没有内容时留空。产品上线前需补齐所有功能的埋点；具体口径未确认时不编造事件或指标。
5. **排期**：固定放以下五列表头和一行空白，由用户和同事手动填写、确认。agent 不填任务、负责人、优先级、日期或状态。动态进展以现行项目排期记录为准。

## 第二章图示与小节写法

以下配图规则适用于第二章章首总览及各功能小节的每张产品图，包括流程图、时序图和思维导图。各功能二级标题下遵循先图后文：先呈现嵌入关键 UI／原型页面的功能图，再补简明扼要的文字说明以及图上无法判断的必要规则、异常、恢复方式和验收条件；同一规则只在一处定义。

- **功能图**：按功能特点选择图表，可以使用一种，也可组合使用。
   - 涉及用户的时序性操作或数据流转时，必须有流程图或时序图，表达主要步骤、关键分支或交互关系。
   - 信息组织、信息展示较强的功能，可用简要思维导图帮助理解信息层级和组织方式；同时涉及操作或数据流转时，搭配流程图或时序图，不以思维导图替代。
   - 逐图按目标对象确认、关键输入／选择、主要结果、重要异常和核心信息展示识别关键节点，各关键节点必须在同一画板的对应位置嵌入真实 UI／原型截图。仅有链接、图外截图或任意一张配图不满足要求；纯业务判断和后台处理用文字节点表达。
   - 关键页面紧邻对应步骤或信息节点，标明页面／状态名称和具体 Figma node 链接，尺寸协调、保持原始比例且内容清晰；截图数量和布局按功能需要安排。
   - 连线依据已确认业务规则，状态示例明确标识；文字、形状、截图和连线可分别编辑。
- **结构化文字**：简明说明功能目的、入口与核心行为，按需用短列表或表格阐明图中无法判断的必要规则、异常、恢复方式和验收条件，避免长段落或逐图复述。

设计素材优先使用现行 UI；没有 UI 时使用原型，并标明来源类型。已有可用入口直接使用；不知道从哪里找时向用户询问一次。缺少或无法核验的对应截图，逐处标待补并报告缺口，按入口约定索取一次；可先完成有依据的文字与功能图，配图保持待完成状态，不虚构界面。交付前逐张核对关键节点与截图的对应关系、覆盖情况、来源及云端显示。

## 文末详细变更记录

在正文之后放不参与正文编号的“详细变更记录”表，记录版本、日期、实质变化与对应位置／增量版入口。可列当前版和此前版本，文首只有摘要，文末留可追溯细节；同一版本多项变化合为一行，不逐字重复维护文首描述。产品团队内部小版本变化在此留痕，已交付大版本的详细差异关联对应增量版。

## 完稿检查

- 封面已实际设置为文档封面资源，并回读确认；主题、清晰度和裁切合适，生成图片尺寸为 2000×400，生成不可用或不达标时使用合适的内置封面。
- 开头信息完整：版本表五字段顺序准确，仅一行当前信息，表头内的历史链接可到达文末记录；资料表位于版本表后、第一章前，链接具体、有效，缺口可见。
- 概述的三个小节完整，名词解释是表格，1.3 有原生可编辑思维导图，概括全文主旨和内容结构。
- 章首功能总览覆盖本 PRD 的功能主线，优先用流程图、时序图等呈现操作顺序、关键分支与结果，未用静态分类替代使用流程。
- 每个功能二级节先呈现嵌入关键 UI／原型页面的功能图，再补简明的结构化文字说明；涉及用户操作顺序或数据流转时有流程图／时序图，信息组织与展示可用思维导图说明，必要规则、异常、恢复和验收条件完整且未重复定义。
- 关键页面覆盖理解功能所需的步骤和重要分支，与步骤／信息节点对应明确，名称和具体 node 链接准确；缺页已标待补，状态示例标识清楚，云端实际显示清晰。
- 第 4 章“埋点、分层等”存在；暂无内容时为空。第 5 章排期有且仅有固定五列表头和一行空白。
- 文末详细变更记录可达；版本号与需求基线、交付状态一致，同一事实没有多处完整定义。
- 正文所有图示已按入口要求核验原生节点可编辑，文字、形状、截图和连线可分别操作；实际飞书成品使用原生表格、自动标题编号和规定间距，任务范围外的资源保留。
- 若另有开发交付任务，先确认本轮最终小版本，再按入口读取增量版说明；仅维护全量版时不加载增量版说明。
